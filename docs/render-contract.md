# 渲染契约 v0.1

设计（Claude）与工程（Codex）之间的接口。Claude 起草；Codex 可以对任何条目提修改，写在 `docs/requests.md`。
本文规定"要什么"和接口形状。管线怎么实现（无头浏览器、编码参数、缓存方式等）由 Codex 决定。

## 输出规格

| 项 | 值 |
|---|---|
| 分辨率 | 1920×1080 |
| 帧率 | 30 fps |
| 时长 | 约 180 秒（以配音实际时长为准） |
| 视频 | H.264 或更高，交付 YouTube 用的高码率母版 |
| 音频 | 48 kHz；整体响度 −14 LUFS，真峰值 ≤ −1 dBTP |
| 字幕 | SRT，由配音段落时间戳生成，不烧录 |

## 画面代码的形状（Codex 可改）

帧代码是**原生 ES 模块**（JavaScript），写在 `design/`，绘制到 Canvas 2D，不需要构建步骤，无头浏览器可以直接加载。选 Canvas 2D 的理由是中文排版和字体控制最直接。

已有的部分（样张阶段写的，正片会沿用）：

| 文件 | 内容 |
|---|---|
| `design/lib/palette.js` | 颜色、网格、字体、画幅常量 |
| `design/lib/wall.js` | 纸面、噪声字、句子（含凝结动画）、光标 |
| `design/lib/compose.js` | `renderScene(ctx, W, H, scene)`：把一个场景状态画成一帧 |
| `design/lib/blur.js` | 运动模糊的**参考实现**，画面验收以它为基准 |
| `design/styleframes/` | 静帧样张和动态样张，`.claude/launch.json` 里的 `design-static` 可以启动预览 |

正片的入口模块已交付：`design/film/film.js`（分镜在 `design/film/storyboard.js`）。导出：

```js
export async function load();        // 加载台本、时间轴、字体；第 0 帧之前完成
export function duration();          // 全片秒数
export function cameraAt(t, scale);  // → { x, y, zoom }，scale = 输出宽度 / 1920
export function render(ctx, t);      // 画第 t 秒的画面，分辨率取 ctx.canvas 的尺寸
```

渲染分辨率变了也不用改代码：所有绘制都以墙面坐标为准，把 `zoom` 乘以缩放比例即可（动态样张就是这样出半分辨率预览的）。

- `t` 单位为秒。`render` 必须是 `t` 的**纯函数**：同样的 `t` 画出同样的画面
- 随机数一律用带种子的哈希，不用 `Math.random`，不读 `Date.now`
- `cameraAt(t)` 单独导出，供管线判断当前是否在移动、决定运动模糊的样本数

## 时间轴：声音先行，画面对齐

1. Codex 按 `script/` 的段落 ID 生成配音，一段一个文件：`audio/vo/S01.wav`……
2. Codex 产出 `audio/vo/timing.json`，记录每段在成片中的起止时间（含段间停顿）：

```json
{ "segments": [ { "id": "S01", "start": 0.80, "end": 4.62 } ] }
```

3. 画面的所有提示点都相对段落来写，比如"S05 开始后 0.3 秒，镜头开始移动"，不写死的绝对时间。台本或配音改了，画面会自动重新对齐。
4. 如果 MiniMax 能给出字级时间戳，请一并保存为 `audio/vo/S01.words.json`，"凝结"动画可以精确到字。拿不到也没关系，按段落对齐就行。

## 运动模糊

- 模拟 180° 快门：第 `n` 帧的曝光区间为 `[n/30, n/30 + 1/60]`
- 在曝光区间内采样若干子帧并取平均。**混合在线性光空间中做**，不要在 sRGB 空间里直接平均
- **自适应采样**：静止时只采 1 个样本，保证静止画面锐利。移动时，样本间距不要超过约 1.5 px，否则细笔画会出现一道道离散的重影。v0 里写的"上限 16"不够：峰值速度时位移约 110 px，需要 70 个以上样本。参考实现的上限是 128
- 可选优化：镜头**纯平移**且画面内没有局部动画时，"渲染一次再沿运动方向做线性光空间的盒式模糊"和子帧平均在数学上等价，速度快几十倍。用不用由 Codex 决定，结果要和参考实现一致
- 画面中的局部动画（字的凝结、光标闪烁）同样按子帧采样，不另做处理

## 音效提示点

Claude 会在分镜阶段输出 `design/cues.json`，列出每个音效的类型和时间（相对段落）：

```json
{ "cues": [ { "type": "move", "seg": "S03", "offset": 0.2, "duration": 1.4 },
            { "type": "settle", "seg": "S03", "offset": 1.6 } ] }
```

`move`：镜头移动的气流声，长度等于移动时长；`settle`：字凝结的一声轻响。声音的具体设计归 Codex，风格要求见 `docs/brief.md`。

## 配音参数

- 全片使用同一个音色和同一组参数，记录在 `audio/vo/config.json` 中，不手调单段
- 台本里标注了多音字读音和停顿，见 `script/` 各文件的"读音"说明
- 每段生成后，用语音识别转写回文字，与台本比对，输出差异报告。Claude 用这份报告检查读错的字
